1. Problem Statement

Traditional paper-based and centralized land registry systems frequently suffer from issues of integrity, data vulnerability, unauthorized alteration of property ownership records, and lack of transparent historical audit trails. In centralized database architectures, an administrator or unauthorized entity can modify ownership records without leaving a detectable cryptographic imprint. There is a need for an immutable, verifiable, and transparent record-keeping mechanism that ensures every transfer is chronologically bound, verifiable, and tamper-evident.

Disclaimer: This academic application is designed to demonstrate blockchain data structure principles and does not grant legal title or replace statutory government land registries.
2. Proposed Solution

The proposed solution implements a Python-based blockchain from scratch that begins with a well-defined Genesis Block (Block 0) with a hardcoded previous hash of "0". Subsequent land ownership transfers are packaged into discrete blocks, hashed using standard SHA-256 cryptography, and linked sequentially using the previous block's hash. A verification algorithm continuously audits the integrity of the chain and instantly flags any unauthorized modifications.

3. Objectives
  1. To construct a Genesis Block (Block 0) as the foundation of the chain.
  2. To implement cryptographic SHA-256 hashing using standard hash primitives.
  3. To record land transfer transactions (Land ID, survey number, seller, buyer) into discrete blocks.
  4. To establish strict cryptographic linkage using previous hash pointers.
  5. To implement a verification function that audits the entire blockchain integrity.
  6. To demonstrate tamper detection by simulating unauthorized data alteration.
  7. To deliver a clean, intuitive web interface suitable for academic presentation and viva examination.
4. Algorithm
1. Start.
2. Create Genesis Block.
3. Set Genesis Block previous hash to "0".
4. Calculate Genesis Block SHA-256 hash.
5. Accept land transfer details (Land ID, survey number, location, previous owner, new owner, date, type).
6. Create a new land transfer block.
7. Obtain the previous block hash.
8. Store the previous hash in the new block.
9. Calculate the new block SHA-256 hash.
10. Add the block to the blockchain list.
11. Repeat for additional transfers.
12. Validate the blockchain.
13. Compare each block's hash with its recalculated hash.
14. Compare each block's previous hash with the previous block's hash.
15. Display VALID if all checks pass.
16. Display INVALID if any check fails.
17. Stop.

Result

The implemented system successfully demonstrates Genesis Block generation, land transfer transaction recording, real SHA-256 cryptographic hashing, sequential previous-hash linkage, blockchain formation, mathematical validation, and instant tamper detection.

Key Advantages
  • Tamper-evident linked list structure
  • Complete transparent historical traceability
  • Cryptographic SHA-256 integrity assurance
  • Direct verification without proprietary tools
Limitations
  • Academic demonstration using in-memory state.
  • Not integrated with statutory government registries.
  • Does not establish legal real-world land title.
  • Single-node prototype without distributed P2P consensus.
Future Scope
  • Transition to permissioned distributed networks (Hyperledger Fabric).
  • Digital signatures using asymmetric public-private key pairs (ECDSA).
  • Smart contracts for automated escrow and tax clearance.
  • Integration with government GIS land survey databases.
